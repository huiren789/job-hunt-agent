# job-hunt-agent

一套找实习的方法和执行工具。方法部分告诉你怎么筛岗、怎么判断回复、怎么把反馈变成下一步行动；工具部分是一个本地脚本，帮你只读地盯着招聘站的投递状态。

仓库里有两部分能跑的代码：`agent/`（反馈归因、数据箱、改进计划生成、CLI）和 `automation/detect.py`（招聘站只读检测器）。筛选规则、话术这些是方法文档，需要你自己落到表格或笔记里。这不是一个"clone 下来全自动投递"的项目。

## 解决什么问题

投了很多岗没回音，通常卡在两个地方：不知道该投什么（海投一堆不匹配的），以及收到回复后不知道下一步做什么（拒了不知原因、过了不知准备什么、客套话当成真反馈）。

这个项目做三件事：

1. **投之前用固定规则筛**，把不匹配的岗挡掉，省下海投的时间。
2. **收到回复先分类**，再决定回什么、存什么——客套婉拒不进数据箱，只有带具体理由的才存。
3. **攒够真样本后**才生成改进计划，把反馈变成"该补什么"，而不是堆一堆拒信。

## 主要功能

### 反馈分析：`agent/`

把 `docs/02`、`04`、`05` 的方法落成了代码：

- **真反馈过滤**：客套婉拒、系统通知、含糊回复一律不入库。规则里专门处理了"感谢投递，但因为缺 X"这种客套+具体理由混合的情况——它算真反馈。
- **8 类归因**：规则打分 + 置信度（high/medium/low）。置信度低归"其他"，不硬套。LLM 是可选增强，只在规则判不出来且你主动注入 client 时才调用——归因是统计口径，必须可复现，不能让模型每次给不同答案。
- **数据箱**：只写真样本，按原话和 source_id 双重去重，可统计归因分布。
- **改进计划**：按归因次数排 P1/P2/P3，每条建议附支撑原话；没有真样本时明确拒绝生成。
- **HTML 看板**：单文件、无外部依赖，离线可打开。

一个命令行入口串起全流程，见下方「使用」。

### 能跑的代码：`automation/detect.py`

- 用你自己的浏览器登录态读招聘站，检测新的消息 / 投递状态。
- 按关键词判三类：想聊 / 过了 / 拒了（判定顺序固定，见 `docs/02`）。
- 如果你的页面是"按状态分 tab"的投递页（例如有面试/不合适/录用几个标签），配置后可以逐个 tab 读。
- 结果去重后写到本地 `outbox.json`。
- **只读**：不投简历、不发消息、不点任何提交按钮。遇到验证码/滑块直接跳过该平台。

平台信息（网址、卡片选择器、关键词、浏览器类型）全部写在 `config.py`，脚本本身不含任何具体网站的信息。

## 安装

需要 Python 3.8+ 和一个本机浏览器（Chrome 或 Edge 都行）。

```bash
git clone https://github.com/huiren789/job-hunt-agent.git
cd job-hunt-agent
pip install -r automation/requirements.txt
```

`requirements.txt` 只有一个依赖：`playwright>=1.40.0`（只给 `detect.py` 用）。`agent/` 模块和 CLI 只用 Python 标准库，零额外依赖。

`agent/` 模块有 18 个单元测试（标准库 unittest，零额外依赖）。跑测试（可选，CI 会自动跑）：

```bash
python -m unittest discover -s tests -v
```

配自己的平台（只用检测器时才需要）：

```bash
cp automation/config.example.py automation/config.py
```

编辑 `config.py` 里的 `PLATFORMS`：填消息页网址、独立登录态目录、消息卡片选择器。选择器要打开页面用开发者工具确认——仓库给的是通用候选，不保证匹配你的网站。

## 使用

首次登录每个平台（会开一个独立浏览器窗口，手动登录后 90 秒自动保存）：

```bash
python automation/detect.py --login platform_a
python automation/detect.py --login platform_b
```

平台名就是 `config.py` 里 `PLATFORMS` 的键，改成你自己的名字即可，不叫 platform_a 也行。

日常检测（无参数）：

```bash
python automation/detect.py
```

想看某个平台有哪些键可用，直接看 `config.py` 的 `PLATFORMS`。

### 反馈分析 CLI

先拿合成示例试一遍（不碰你的真实数据）：

```bash
# 只看判定，不入库
python -m agent.cli check "因为需要C++经验，您技术栈不符"

# 批量导入示例反馈（公司名都是"示例公司X"，无真实信息）
python -m agent.cli add-texts examples/sample_feedback.json

# 看归因分布
python -m agent.cli stats

# 生成 HTML 改进计划看板
python -m agent.cli report --out 改进计划.html
```

默认数据箱写在 `data/databox.json`（已在 `.gitignore` 里）。6 条示例里有一条客套话会被挡掉，剩下的进数据箱——正好演示"不存客套"的规则。

加自己的反馈用 `add`：

```bash
python -m agent.cli add "对方原话" --company 公司名 --role 岗位名 --platform 平台
```

## 输入 / 输出示例

**输入 1：`config.py` 里的一段平台配置**

```python
PLATFORMS = {
    "my_jobs": {
        "url": "https://example.org/my/deliveries",
        "profile": BASE / "profile_my_jobs",
        "message_selectors": [".delivery-item", "[class*='application-card']"],
        "mode": "messages",
        "status_tabs_selector": ".tab",
        "feedback_tabs": ["面试", "不合适", "录用"],
    },
}

REJECT_WORDS = ["不合适", "未通过", "感谢参与", "not selected"]
```

**输入 2：页面上一条消息卡片被读到的文本**

```
数据分析实习生 字节跳动 2026-11-21 不合适
```

**输出 1：终端日志**

```
[2026-11-24 00:20:24] === 本地反馈检测启动（只读，不投递不发消息）===
[2026-11-24 00:20:24] --- my_jobs：https://example.org/my/deliveries
[2026-11-24 00:20:31]   tab[不合适]: 20 张卡片
[2026-11-24 00:20:31] === 完成：新判定 1 条 → .../outbox.json ===
[2026-11-24 00:20:31]   - my_jobs / 拒了 / 数据分析实习生 字节跳动 2026-11-21 不合适
```

**输出 2：`outbox.json`**

```json
{
  "items": [
    {
      "platform": "my_jobs",
      "tab": "不合适",
      "judge": "拒了",
      "text": "数据分析实习生 字节跳动 2026-11-21 不合适",
      "detected_at": "2026-11-24T00:20:31"
    }
  ],
  "last_run": "2026-11-24T00:20:31"
}
```

注意：这条"不合适"只有状态、没有对方给的理由。按 `docs/04` 的规则，它留在 outbox 做记录，**不会进拒因数据箱**。只有拿到"因为你缺 X"这类具体原话，才值得存。

**反馈分析的输出**：跑 `python -m agent.cli check "因为岗位需要 C++ 经验，您技术栈不符"` 得到：

```
判定: genuine
理由: 包含具体理由词
归因: 技术栈不符 (medium)
命中具体词: 因为, 需要, 不符, 经验, 技术栈
```

而 `check "感谢投递，祝顺利"` 得到：

```
判定: non_genuine
理由: 仅客套/通知，无具体理由
```

`report` 生成的 HTML 看板包含归因分布条形图、P1/P2/P3 建议、每条建议的依据原话。都是纯离线单文件。

## 边界

- 仓库里没有真实个人信息、简历、投递记录、邮箱账号或登录态。登录态和 `outbox.json` 都在 `.gitignore` 里，不会进 git。
- `detect.py` 只读。遇到极验、滑块等验证会跳过——不绕过、不硬闯，这是为了你的账号安全。
- 仓库里**没有自动发邮件的代码**。`docs/02` 写的发信八条锁是规则，需要你自己用邮件工具实现；是否启用、授权范围由你决定。
- `agent/` 的归因是规则驱动、可复现的；LLM 是可选增强，默认不启用，需要你自己注入兼容 OpenAI 接口的 client。
- 改进计划看板只反映已收到的真反馈，不构成"补了就能过"的承诺；建议是否采纳由你决定。
- 网站会改版，选择器和网址失效是正常的，改 `config.py` 即可。

## 适用

- 在校生 / 应届生，愿意按规则筛岗、想把拒因攒成数据的人。
- 不适合的场景：想要开箱即用的全自动投递工具。这个仓库不是。
