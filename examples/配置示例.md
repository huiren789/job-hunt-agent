# 配置示例：把通用模板改成你自己的

## 1. 先填基本盘（写在自己的笔记里，不进仓库）

```
年级/身份：
专业：
可投入时间：学期内每周几天×几小时 / 假期是否全职 / 能否远程
技术证据：做过的项目，带数字和链接
地域/生活约束：
```

这部分决定筛选规则（docs/01）和话术（docs/03）怎么落地，**不要提交到公开仓库**。

## 2. 配置本地检测器

```bash
cp automation/config.example.py automation/config.py
```

然后编辑 `config.py`：
- `PLATFORMS`：填你要监测的平台消息页 URL，每个平台一个独立 `profile` 目录；
- `message_selectors`：打开消息页，用开发者工具找到消息卡片的 class，填进来（可填多个候选）；
- `PASS_WORDS` / `REJECT_WORDS` / `WANT_CHAT_WORDS`：按中文语境补关键词；
- `BLOCK_WORDS`：保留默认即可，遇到验证会跳过。

## 3. 首次登录 + 日常检测

```bash
python automation/detect.py --login platform_a   # 扫码登录，独立窗口
python automation/detect.py --login platform_b
python automation/detect.py                       # 日常只读检测
```

输出 `outbox.json`（已在 .gitignore 中，不会上传）。

## 4. 落地文档体系

把 `docs/` 的六份方法论、`templates/` 的两个模板，复制到你自己的笔记/表格工具里，
按第一步的基本盘改成你的版本。真实数据（投递记录、拒因、简历）只留在本地。

## 5. 可选：自动化定时任务

如果你用支持定时任务的 Agent，可建三个任务：
- 每工作日早上：按筛选规则检索新岗，产出清单；
- 每工作日两次：邮箱闭环检测 + 高置信度自动回复；
- 按需：用户问"我该补什么"才生成改进计划。

任务提示词里只写方法论和规则，不写任何真实个人信息。
