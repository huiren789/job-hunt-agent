# 02 · 反馈判断

## 一、五类判断（顺序不可颠倒）

```
排除系统邮件 → 想进一步聊 → 过了（正式面试邀约） → 拒后回复 → 拒了 → 其他
```

| 类别 | 识别 | 处理 |
|---|---|---|
| 系统邮件 | 自动回复 / 退信 / 通知 | 跳过，不进任何数据 |
| 想进一步聊 | 约电话、问时间、"方便聊聊吗" | 高置信度下自动跟进（需预授权） |
| 过了 | 正式面试邀约（时间/地点/轮次明确） | 写追踪表 + 提醒本人，永不自动确认 |
| 拒后回复 | 对你追问的回复（见三级匹配） | 有具体理由才入数据箱 |
| 拒了 | 明确拒绝（含"不合适/感谢参与"） | 高置信度下发一次追问（需预授权） |
| 其他 | 含糊、拿不准 | 不自动发、不入库，只记日志 |

## 二、反馈价值层（决定要不要存）

- **真反馈**：具体指出不足（技术栈 / 项目 / 专业 / 时间）或给改进方向 → 逐字原话存入数据箱。
- **客套**：感谢投递、岗位招满、祝顺利、模板婉拒 → **不存、不标未回复、不建空记录**，只记日志。
- 拿不准 → 归"其他"。宁可漏存，不可脑补理由。

## 三、拒后回复三级匹配（判断这条回复对应哪个岗位）

1. 邮件头 `In-Reply-To` / `References` 命中 replyMap（最可靠）。
2. 主题 `Re:` + 岗位名 + 状态词（如"被拒"）。
3. 正文含理由词，且来自你确实投过的联系人。

三级都不中 → 归"其他"，不硬套。

## 四、去重与游标

- 消息ID做去重，追踪表用"邮件message_id"列再去重一次（双保险）。
- 游标用时间戳，且**只在处理成功后更新**；分页 cursor 不持久化。
- 含 token / 密钥 / 撤销链接的正文片段，禁止写入任何文件。

## 五、自动发信八条锁（如启用）

1. 只对高置信度的"拒了追问"和"想聊跟进"两类自动发；
2. 话术取固定模板，只替换称呼，不临场生成；
3. 只回原线程，不群发新邮件；
4. 每天总量设上限；
5. 发了就写回状态：追问状态、replyMap、发送日志、message_id；
6. 内容含糊一律不发；
7. 全程留日志，可复盘；
8. 用户一句话（如"停掉自动发"）即关闭总闸。

总闸放配置文件里，默认关闭更稳妥；开启需用户显式授权。
