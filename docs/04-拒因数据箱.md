# 04 · 拒因数据箱

这是整套系统的"真样本库"。改进计划只从这里取材。

## 一、存 / 不存

**存**（真反馈）：
- 具体指出不足：技术栈、经验、项目、专业口径、到岗时间、薪资预期；
- 给出改进方向："如果会 X 就好了""建议补 Y"；
- 对方原话逐字保留，不改写、不归纳成自己的话。

**不存**：
- 客套婉拒（感谢投递 / 岗位招满 / 祝顺利）；
- 自动回复、系统通知；
- 含糊其辞、拿不准的；
- 只是发了追问、还没拿到理由的（不建空记录）。

理由：客套话进了数据箱，改进计划就会被"祝你好运"污染，失去意义。

## 二、字段 scheme（每条一行）

```
日期 | 公司 | 岗位 | 平台 | 对方原话 | 归因 | 改进建议原话 | 待补技能 | 追问话术 | 追问状态 | 拒信message_id | 追问message_id | 追踪表行号
```

## 三、归因分类（8 类，用短名写入）

1. 技术栈不符
2. 经验不足
3. 专业口径
4. 到岗时间
5. 薪资
6. 沟通表达
7. 岗位关闭
8. 无反馈（>7天）

每类记录：判定关键词、本质、该补什么、对应追问话术。**归因值统一用短名**，别一处写全称一处写简称，否则统计对不上。

## 四、与"不符岗收录"的区别

- 本数据箱：投出去之后，对方给了**具体理由**的拒因。
- 不符岗收录（docs/06）：投递**之前**就判定不适合的岗和原因（年级卡 / 时间冲突 / 方向不符等）。
- 两者不混：前者是反馈数据，后者是筛选规则的校准依据。

## 五、生成改进计划的纪律

- 没有真样本 → 明确拒绝生成，说明数据不足；
- 有样本 → 按归因聚合次数，排优先级；
- 建议必须能对应到 samples，不能凭空发明"大家都说你缺 X"。
