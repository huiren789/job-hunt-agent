# 05 · 改进计划（按需生成）

## 触发

用户问"我该补什么 / 生成改进计划 / 总结一下拒因"时才生成。**不自动生成**，不主动推送。

## 前置条件

数据箱里必须有真样本（见 04）。没有就明确拒绝：
> "目前数据箱还没有带具体理由的真样本，生成不了有意义的改进计划。先让流程跑一段时间攒反馈。"

绝不编造理由、不拿客套话充数。

## 生成流程

1. 读数据箱全部真样本 → 按 8 类归因聚合，统计每类次数。
2. 按次数排优先级：P1（高频）/ P2（中频）/ P3（单次但严重）。
3. 落到三维度，每个建议都要能指回具体样本。

## 三维度结构

### 维度一 · 技能补强
- 高频被点名的技术栈 / 能力；
- 每条写：被点名几次 → 对应哪句原话 → 建议怎么补（做项目 / 上课 / 认证）。

### 维度二 · 简历 / 话术调整
- 从反馈反推：表述是否没说清、证据是否没给够、话术是否踩了 AI 味；
- 具体到"把 X 改成 Y"，不是泛泛说"优化简历"。

### 维度三 · 岗位方向校准
- 哪类岗位反复被拒 → 是不是方向选错；
- 哪类岗位反馈好 → 是不是该加投；
- 结合不符岗收录（docs/06）的统计，调整筛选规则的门槛。

## 输出

生成一个看板（HTML/Markdown 均可），章节：
1. 样本概览（几条、时间跨度、归因分布）
2. 维度一 · 技能补强
3. 维度二 · 简历/话术调整
4. 维度三 · 岗位方向校准
5. 优先级排序（P1/P2/P3 + 具体行动）

## 纪律

- 每次生成都标日期和样本来源；
- 建议不承诺结果（"补了就能过"这种话不说）；
- 不替用户决定，只给分档建议。
